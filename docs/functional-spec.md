# Functional Specification

## 1. Назначение

**СтудСемья** — веб-приложение для курирования вопросов студенческих семей.

Система предоставляет:

* структурированную базу информационных материалов;
* поиск по материалам;
* понятное представление юридической информации;
* AI-ассистента для разбора ситуации пользователя;
* рекомендации релевантных статей.

AI-ассистент является справочным инструментом и не заменяет консультацию юриста.

## 2. Роли

### Анонимный пользователь

Может:

* просматривать главную страницу;
* просматривать статьи;
* искать статьи;
* фильтровать статьи;
* открывать отдельные статьи;
* использовать AI-ассистента;
* создавать и продолжать чаты;
* получать рекомендации статей от AI.

Авторизация для публичной части не требуется.

### Редактор / юрист

Может:

* авторизоваться;
* просматривать свой профиль;
* изменять профиль;
* изменять пароль;
* создавать статьи;
* читать статьи;
* редактировать статьи;
* удалять статьи;
* сохранять черновики;
* публиковать статьи;
* добавлять соавторов;
* удалять соавторов.

### Модератор / администратор

Может:

* авторизоваться;
* управлять аккаунтами редакторов;
* создавать редакторов;
* просматривать редакторов;
* изменять редакторов;
* активировать/деактивировать редакторов;
* просматривать журнал действий;
* фильтровать журнал;
* открывать детали действий.

## 4. Главный публичный функционал

### Главная

Пользователь должен иметь возможность:

* перейти к статьям;
* выполнить поиск;
* открыть AI-ассистента;
* выбрать категорию.

### Статьи

Каталог предоставляет:

* список статей;
* поиск;
* фильтр по категории;
* сортировку/фильтр по дате обновления;
* пагинацию.

### Статья

Страница статьи содержит:

* категорию;
* заголовок;
* краткое описание;
* содержание;
* кому положена мера поддержки;
* необходимые документы;
* регион;
* официальный источник;
* ограничения;
* дату обновления;
* связанные статьи;
* переход к AI-ассистенту.

## 5. AI-ассистент

Пользователь описывает свою ситуацию естественным языком.

Backend:

1. получает сообщение;
2. загружает системный промпт;
3. выполняет поиск по базе знаний;
4. формирует контекст;
5. отправляет запрос в OpenCode API;
6. использует модель `Deepseek-v4-flash`;
7. получает ответ;
8. сохраняет сообщение пользователя и ответ AI;
9. возвращает ответ frontend;
10. возвращает релевантные статьи.

Архитектура должна позволять изменять:

* модель;
* системный промпт;
* temperature;
* max tokens;
* базу знаний.

без изменения frontend.

## 6. Системный промпт

Системный промпт является конфигурацией AI.

Он должен содержать как минимум:

* роль AI;
* назначение ассистента;
* правила формирования ответа;
* запрет выдавать себя за юриста;
* требование опираться на предоставленную базу знаний;
* правила работы с отсутствующей информацией;
* формат рекомендаций статей;
* требования к юридическим оговоркам.

Пример логики:

```text
Ты — справочный AI-ассистент проекта СтудСемья.

Отвечай на основании предоставленной базы знаний.
Не придумывай льготы, суммы, сроки или нормативные положения.
Если в базе знаний недостаточно информации, явно сообщи об этом.
Не выдавай себя за юриста.
В конце ответа рекомендуй релевантные материалы, если они найдены.
```

Фактический production prompt должен храниться в настройках приложения, а не быть жёстко зашит в frontend.

## 7. База знаний AI

Основной источник знаний:

* опубликованные статьи;
* отдельные KnowledgeDocument.

На первом этапе используется SQLite FTS5.

Поиск:

```text
user question
      ↓
FTS5
      ↓
top relevant documents
      ↓
context
      ↓
Deepseek-v4-flash
```

В AI-контекст передавать только релевантные материалы.

Не передавать всю базу знаний при каждом запросе.

## 8. Редактор

Редактор может:

* создать статью;
* сохранить черновик;
* изменить статью;
* удалить статью;
* опубликовать статью;
* добавить соавтора;
* удалить соавтора;
* открыть предпросмотр.

При публикации статья становится доступна:

* публичному каталогу;
* поиску;
* AI-базе знаний.

При изменении опубликованной статьи AI должен использовать актуальную версию после обновления индекса.

## 9. Администратор

Администратор управляет:

* редакторами;
* статусами аккаунтов;
* журналом действий;
* настройками AI.

Дополнительно администратор может изменять:

* системный промпт;
* используемую модель;
* параметры генерации;
* включение/выключение базы знаний.

* article.deleted;
* article.published;
* coauthor.added;
* coauthor.removed;
* account.created;
* account.updated;

## 11. Состояния

Обязательно:

* loading;
* empty;
* error;
* success;
* 404;
* AI unavailable;
* AI loading;
* no search results.

## 12. Критерии готовности

Готовая система должна позволять:

1. анонимному пользователю найти статью;
2. открыть статью;
3. выполнить поиск;
4. воспользоваться AI;
5. получить ответ AI;
6. получить рекомендации статей;
7. сохранить историю чата;
8. редактору создавать и публиковать статьи;
9. редактору управлять соавторами;
10. администратору управлять редакторами;
11. администратору просматривать логи;
12. администратору изменять AI system prompt;
13. AI использовать базу знаний;
14. работать без Docker;
15. запускать БД локально через SQLite3.
