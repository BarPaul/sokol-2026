# Design Reference

## 1. Источник истины

Визуальным источником истины являются предоставленные Figma-экраны из ZIP.

Functional requirements не должны использоваться как основание для изменения визуального решения.

При реализации:

1. найти соответствующий screenshot;
2. определить route;
3. определить состояние;
4. реализовать UI;
5. сравнить результат с screenshot.

Не создавать новый дизайн, если соответствующий элемент уже существует в референсах.

## 2. Архитектура интерфейсов

В проекте присутствуют три группы интерфейсов:

## 3. Public UI

### Header

Используется единый header публичной части.

Основные переходы:

* Главная;
* Статьи;
* Поиск;
* AI-помощник.

Для mobile использовать navigation из соответствующего mobile reference.

### Главная

Основная задача страницы — быстро привести пользователя к информации.

Приоритет:

1. поиск;
2. категории;
3. статьи;
4. AI-помощник.

Использовать существующие hero, карточки, CTA и footer из Figma.

Не менять порядок блоков без необходимости.

### Каталог статей

Карточка статьи содержит:

* категорию;
* заголовок;
* краткое описание;
* дату обновления;
* время чтения.

Фильтры:

* категория;
* период/дата обновления.

### Search

Search page должна визуально показывать:

* поисковую строку;
* запрос;
* количество результатов;
* список результатов;
* фильтры;
* empty state.

### Article

Страница статьи структурируется визуальными блоками:

```text
breadcrumbs
category
title
updated
summary

основной материал

кому положено
необходимые документы
регион
официальный источник
ограничения

AI CTA

related articles
```

Не превращать материал в единый длинный текстовый блок.

## 4. AI Assistant

AI interface состоит из:

```text
sidebar
    ├── список чатов
    └── создание нового чата

main
    ├── welcome / messages
    ├── recommended articles
    ├── suggested questions
    └── input
```

### Welcome state

Показывать:

* название AI-помощника;
* краткое описание;
* предупреждение о справочном характере;
* примеры вопросов;
* input.

### Chat state

Сообщения пользователя и AI визуально различаются.

AI может возвращать карточки рекомендуемых статей.

### Loading

Использовать отдельное состояние:

```text
Анализирую вашу ситуацию...
```

### Error

Использовать отдельное состояние:

```text
AI-помощник временно недоступен.
Попробуйте позже или воспользуйтесь ручным поиском
по базе знаний.
```

* соавторы.

## 14. AI Settings

В интерфейсе администратора добавить отдельный раздел настроек AI.

Он должен позволять редактировать:

### System prompt

Большое многострочное поле.

### Model

Поле/селектор:

```text
Deepseek-v4-flash
```

### Temperature

Числовой параметр.

### Max tokens

Числовой параметр.

### Knowledge base

Переключатель:

```text
Использовать базу знаний
```

### Reindex

Кнопка:

```text
Переиндексировать базу знаний
```

Настройки доступны только администратору.

## 15. Knowledge Base UI

Администратор должен иметь возможность:

* просматривать документы;
* искать документы;
* создавать документ;
* редактировать документ;
* отключать документ;
* удалять документ;
* запускать переиндексацию.

Карточка/строка документа:

* название;
* источник;
* категория;
* статус;
* дата обновления.

## 16. Responsive

### Desktop

Использовать desktop Figma reference.

### Tablet

Использовать tablet reference.

Sidebar может становиться компактнее.

Таблицы могут адаптироваться по ширине.

### Mobile

Использовать mobile reference.

Правила:

* sidebar превращается в mobile navigation;
* таблицы превращаются в карточки;
* формы становятся одноколоночными;
* chat занимает всю доступную ширину;
* CTA остаются доступными;
* горизонтальный overflow не допускается.

## 17. Design tokens

Создать централизованные tokens:

```text
colors
font sizes
font weights
line heights
spacing
border radius
shadows
breakpoints
```

Не размножать значения по компонентам.

Если точное значение доступно в Figma — использовать его.

Если значение невозможно извлечь из screenshot — подобрать ближайшее значение и вынести его в token.

## 19. Visual QA

Каждый реализованный экран проверять по:

* размеру контейнера;
* расположению;
* spacing;
* typography;
* цветовому контрасту;
* border;
* radius;
* shadows;
* iconography;
* состояниям;
* responsive behavior.

При несовпадении сначала корректировать tokens и shared components, а не добавлять локальные hacks.

## 20. Контент

Тексты интерфейса должны соответствовать Figma.

Не заменять реальные тексты lorem ipsum.

Если backend ещё не подключён, использовать seed-данные, максимально соответствующие содержимому референсов.

После подключения backend seed-данные должны быть заменены реальными API-ответами.

## 21. Принцип реализации

```text
Figma screenshot
      ↓
Nuxt page
      ↓
shared components
      ↓
API
      ↓
SQLite
```

AI:

```text
User
 ↓
Nuxt UI
 ↓
/api/assistant
 ↓
AIService
 ↓
FTS5 Knowledge Base
 ↓
System Prompt
 ↓
OpenCode API
 ↓
Deepseek-v4-flash
 ↓
AI response
```

UI не должен знать:

* API key;
* OpenCode endpoint;
* system prompt;
* внутреннюю структуру базы знаний.

Все эти детали находятся на server-side.
